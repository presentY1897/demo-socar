# ADR-006. 부름(탁송 배달) — 가용성에 "탁송 시간"이라는 물리 제약을 넣는다

## 상황

실제 서비스의 부름은 지정한 위치로 차량을 배달해주고, 이용이 끝나면 같은 자리에서
회수한다. 핵심 난점은 요금이 아니라 **가용성**이다: 차량이 존에 "있다"고 해서 부름이
가능한 게 아니라, 직전 이용자의 반납 이후 **탁송 기사가 배달지까지 운전해 갈 시간**이
확보되어야 한다.

## 결정

### 가용성 판정

```
직전 반납 시각(없으면 지금) + 탁송 운전 시간 + 준비 버퍼 20분 ≤ 대여 시작 시각
```

- 탁송 운전 시간은 **배차와 같은 OSM 도로망 A\***를 도심 주행 속도(25km/h)로 계산한다 —
  `TravelTimeEstimator.estimateDrive()`. 도보(배차 추천)와 운전(부름)이 같은 그래프,
  같은 폴백 규칙을 공유한다
- 출발 존은 편도 위치 체인(ADR-005)의 유효 위치 기준 — 편도로 이동해 있을 차량이면
  그 존에서 탁송 거리를 계산한다

### 제약과 요금

- 최소 리드타임 60분, 배달 반경은 존 기준 5km, 편도와 조합 금지
- 부름 요금 = 경로 거리 × 1,500원/km (최소 6,000원, 모의 단가) — 선결제에 포함
- 회수 모델: 이용 종료 후 같은 자리에서 회수 → 차량은 원래 존으로 복귀한 것으로 처리
  (위치 체인에 영향 없음)
- 부름 예약의 시간 변경은 탁송 일정 재검증이 얽혀 미지원 — 취소 후 재예약 안내

## 결과

- 통합 테스트: 요금 포함 결제, 리드타임/반경/편도 조합 거절, **직전 반납과의 간격이
  탁송+준비 시간보다 짧으면 409** (`test/bureum.int-spec.ts`)
- 시간 겹침(EXCLUDE 제약)과 별개로, 탁송 리드는 애플리케이션 계층 검증이다 —
  DB 제약으로 내리려면 예약 사이 "간격 제약"이 필요한데 데모 범위를 넘는다고 판단했다
