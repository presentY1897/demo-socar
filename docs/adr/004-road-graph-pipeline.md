# ADR-004. 전국 도로망 — 전처리 파이프라인 + 지역별 경량 그래프

## 상황

배차 추천의 이동시간을 실제 도로 기준으로 계산하고 싶고, 서비스는 **전국**을 대상으로 한다.
그러나:

- 한국 전체 보행 도로망을 통째로 메모리에 올리면 수백 MB — 배포 대상인 Render 무료 티어(512MB)에서 불가능
- 실시간 외부 길찾기 API는 키 발급·쿼터·비용 문제로 데모에 부적합

## 결정

**"전국을 지원하는 파이프라인"과 "필요한 지역만 싣는 산출물"을 분리한다.**

```
OSM (Overpass API)
   │  scripts/build-graph.ts — 지역 중심좌표 목록 → bbox 질의 → 보행 도로 병합
   ▼
data/graphs/{region}.json.gz — 노드/간선 경량 그래프 (지역당 90KB~660KB)
   │  런타임 lazy load (지역별 1회)
   ▼
GraphTravelEstimator — 격자 인덱스 최근접 스냅 + A* 최단경로
```

- `REGIONS`에 중심 좌표만 추가하면 전국 어느 도시든 같은 파이프라인으로 그래프가 나온다
- 저장소에는 존이 실제로 있는 4개 지역(서울/부산/대전/제주, 합계 약 1.2MB)만 커밋
- 빌드 시 최대 연결요소만 남겨 고립된 도로 파편(경로 탐색 실패 원인)을 제거
- 그래프가 없거나 스냅이 300m 이상 벗어나면 직선거리 × 1.3 폴백 — 서비스는 절대 안 죽는다

## 실측

서울 그래프(성수·강남·홍대 일대 7개 bbox): 54,503 노드 / 64,618 간선 / 655KB(gzip).
오피스(성수동) → 성수역 도보 7분(490m), 서울숲 25분(1.84km) — 직선거리 대비 실제 경로의
우회가 반영된 값이다.

## 트레이드오프

- 그래프는 빌드 시점의 스냅샷 — 도로 변경은 재빌드해야 반영된다 (데모에선 허용)
- 보행 전용 규칙(횡단보도, 육교, 계단 회피)은 단순화했다 — 정밀도가 필요해지면
  `TravelTimeEstimator` 구현체를 외부 API로 교체하는 것이 파이프라인 고도화보다 싸다
