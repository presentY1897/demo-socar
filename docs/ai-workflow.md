# AI 워크플로 — Claude Code로 이 프로젝트를 만든 과정

이 프로젝트는 Claude Code(Anthropic의 코딩 에이전트)와 함께 만들었습니다.
"AI가 코드를 뱉어준다"가 아니라, **의사결정은 사람이, 실행과 검증 루프는 에이전트가**
맡는 분업이 실제로 어떻게 돌아갔는지 기록합니다.

## 진행 방식

### 1. 요구 정의 — 결정은 사람이

시작할 때 에이전트가 결정 지점을 질문으로 정리해 왔고, 다음을 직접 결정했습니다:

- 기술 스택 (NestJS + Next.js PWA), 배포 대상 (Vercel + Render + Neon)
- 기능 범위 — 특히 **오피스 배차 기능의 방향**: "차량을 이용하고 반납하고 그에 맞춰
  사람이 이동하는 시간까지 고려해, 담당자가 판단할 수 있는 의사결정 도구여야 한다"
- 배차 방식(완전 자동 vs 추천+승인 vs 수동+경고) 중 **추천+승인** 선택
- 도로망을 성수 일대 하드코딩이 아닌 **전국 지원 파이프라인**으로 확장하는 방향 전환

### 2. 계획 승인 후 마일스톤 단위 구현

에이전트가 전체 설계안(도메인 모델, 동시성 전략, 배차 스코어링, 배포 구성)을 계획 문서로
제출 → 검토·승인 후 구현 시작. 이후 마일스톤(스캐폴드 → 도메인 API → 프론트 → 테스트/문서)
단위로 커밋을 쌓았습니다.

### 3. 에이전트의 검증 루프

단순 코드 생성이 아니라 매 단계 실행-검증을 돌렸습니다:

- 요금 엔진: 순수 함수로 분리 → vitest 12케이스 (주중/주말 경계, 할인 적용 순서, 음수 입력)
- 배차 스코어링: 테스트 기대값이 틀렸던 케이스를 에이전트가 실행 결과로 발견하고
  구현이 아닌 **테스트를 수정** (구현이 맞았음)
- A* 길찾기: 그래프 빌드 직후 실좌표 5개 구간으로 스모크 테스트
  (오피스→성수역 7분 등 상식선 검증)
- Overpass 기본 서버 접속 불가 → 미러 서버 3곳을 자동으로 탐색해 파이프라인 완주

### 4. 사람이 개입한 지점

- 중간에 "성수 일대 한정을 전국 도로망으로 바꾸자"고 방향을 수정 → 에이전트가
  무료 티어 메모리 제약을 근거로 "전국 파이프라인 + 지역별 산출물" 절충안을 제시, 채택
- Docker 미설치 등 로컬 환경 이슈는 사람이 직접 처리 (sudo 필요 작업)

## 느낀 점 (공고의 "AI Native"에 대한 생각)

- 에이전트에게 맡길 것과 사람이 쥘 것의 경계는 **의사결정과 검증 기준**이다.
  "무엇을 만들지, 어디까지 타협할지"를 사람이 정하면 실행 속도는 압도적으로 빨라진다.
- 에이전트의 산출물은 테스트와 실행 결과로 검증해야 한다. 이 프로젝트의 테스트는
  장식이 아니라 에이전트 루프의 일부였다.
- ADR을 에이전트와 함께 쓰면 "왜 이렇게 했는지"가 코드보다 먼저 남는다 — 리뷰 비용이 준다.
