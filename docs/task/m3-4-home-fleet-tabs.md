# M3-4 — 운영 홈 + Fleet 탭 UI

- 마일스톤: M3 (운영 백오피스 재설계) · 규모 L
- 상태: ☑ 완료
- 의존: M3-3

## 목적

피드백 #3·#4·#5의 화면 반영 핵심. `/dashboard`를 매출 화면에서 **운영 센터** 탭 구조로 개편하고, 그중 운영 홈과 Fleet 탭을 만든다.

## 작업 내용

- [x] `/dashboard` 탭 셸 개편: ① 운영 홈 ② 차량 ③ 작업/배차 ④ 존/계약 ⑤ 고객 ⑥ 회계 (③~⑥은 M3-5·6에서 채움)
- [x] **운영 홈 탭**:
  - 상단 스탯: 지금 운행 중 대수 · 탁송 진행 중 · 오늘 예약 수 · 미배정 작업 수
  - 경고 피드(`GET /ops/alerts`): 연료 부족/보험 만기/계약 만료/지연 반납 — 항목 클릭 시 해당 탭으로 이동
  - 실시간 차량 지도: SSE 텔레메트리로 위치·상태 갱신 (ZoneMap 확장)
- [x] **차량(Fleet) 탭**:
  - 전 차량 표: 상태 배지 · 배정 존 · 연료(게이지) · 주행거리 · 다음 예약 · 보험 D-day, 정렬/상태 필터
  - 행 클릭 → 상세 패널: 센서 값 실시간 · 스마트키 조작 이력 · 도입 비용/보험 · 정비 메모 입력
  - 신규 차량 등록 폼(`POST /ops/vehicles`): 차종·연료·요금제·배정 존·도입 방식/금액·보험

### 작업 문서에 없던 추가 (화면이 요구해서 붙인 것)

| 추가 | 왜 |
|---|---|
| `GET /ops/plans` (OPS 전용) | 등록 폼의 요금제 셀렉트. `POST /ops/vehicles`가 `planId`를 요구하는데 요금제 id는 시드가 만든 cuid라 화면이 알 방법이 없었다. 읽기 전용 조회 1건이고 통합 테스트(200 · 비 OPS 403)를 붙였다 |
| `ZoneMap`의 차량 오버레이 prop | 운영 홈의 실시간 지도. 지도를 새로 만들면 타일·줌·좌표 규약이 두 벌로 갈려서 기존 지도를 확장했다 (`vehicles` 미지정이면 소비자 홈과 동작이 같다) |

### 설계 메모

- **탭 목록·라벨·경고 목적지는 전부 shared가 단일 소스**다(`opsTabSchema` · `OPS_TAB_LABEL` · 서버가 실어 주는 `alert.tab`/`alert.targetId`). 화면은 경고를 눌렀을 때 어디로 갈지 스스로 판단하지 않는다 — 판정이 두 벌이면 경고 피드가 엉뚱한 탭으로 데려간다
- **탭 상태는 `?tab=`으로 시작해 이후는 화면 상태**로 든다. 딥링크는 열리되 탭 전환마다 라우터를 돌려 화면 전체를 다시 마운트하지 않는다. `useSearchParams()`가 정적 프리렌더에서 서스펜스 경계를 요구해 페이지를 얇은 `Suspense`로 감쌌다
- **정렬은 순수 함수로 분리**했다(`lib/ops-fleet.ts`). 빈 값(다음 예약 없음·보험 정보 없음)은 방향과 무관하게 항상 뒤로 — "만기가 급한 순"을 보려는데 정보가 없는 차가 앞에 오면 표가 쓸모없어진다
- **상태 → 색은 shared의 `tone` 한 곳에서 파생**한다(`components/ops/state-style.ts`). 표의 배지와 지도 마커가 같은 근거를 본다
- **매출·차트는 운영 홈에서 걷어냈다** — 회계 탭(M3-6)으로 간다. M3-4~5 사이에는 매출 화면이 잠시 비어 있다
