# M1-7 — 문의 + 사고 접수(모의)

- 마일스톤: M1 (이용 플로우 완성) · 규모 M
- 상태: ☑ 완료
- 의존: M1-2

## 목적

피드백 #9 "차량에 대해서 문의하는 기능과 보험관련 연계 기능". 문의 접수와, 가입한 면책상품 정보를 보여주는 사고 접수(모의) 플로우를 만든다. 실제 보험사 청구 연동은 스코프 아웃 유지(Q5).

## 작업 내용

- [x] **API** (`apps/api/src/inquiries/` 신규 모듈):
  - `POST /inquiries` — category(`VEHICLE`(차량 상태)/`USAGE`(이용 문의)/`ETC`) · body · vehicleId?/rentalId? 연결
  - `GET /me/inquiries` — 내 문의 목록(상태·답변 포함). 답변 기능은 백오피스 M3-5
- [x] **API** — `POST /rentals/:id/incident` (rentals 모듈):
  - 상황 설명 + 사진(M1-2 재사용) → `IncidentReport` 저장
  - 응답에 해당 예약의 면책상품 티어·자기부담금(`INSURANCE_META`)·모의 보험사 안내 포함
- [x] **웹**:
  - 문의 작성 폼(카테고리·본문) + 내 문의 목록 — 마이페이지 성격의 진입점(AppShell 또는 예약 상세)
  - 사고 접수 플로우: 이용 중 예약 상세에서 "사고 접수" → 설명+촬영 → 접수 완료 화면에 면책/자기부담금 안내

## 산출물

- inquiries 모듈(신규) · rentals `incident` 액션 · 문의/사고 UI · shared 스키마

## 완료 기준

- 문의 접수 → 내 목록에 OPEN 상태로 표시
- 사고 접수 완료 화면에 가입 면책상품과 자기부담금 금액이 정확히 노출 (통합 테스트로 검증)

## 테스트

- **백엔드(통합)**: 문의 생성→내 목록 조회 · incident 응답에 가입 면책 티어·자기부담금 포함 검증 · 타인 rental에 접수 403
- **프론트(MSW)**: 문의 폼 제출→목록 갱신 · 사고 접수 완료 화면에 면책 정보 렌더 · 필수 입력 검증 에러 표시

## 결과 (2026-09-01)

### 엔드포인트

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| POST | `/inquiries` | `{ category, body, vehicleId?, rentalId? }` | `Inquiry`(status `OPEN`) |
| GET | `/me/inquiries` | — | `Inquiry[]` (최신순 50건) |
| POST | `/rentals/:id/incident` | `{ description, photos[0..5] }` | `{ incident, insurance, insurer }` |

- 문의에 `rentalId`를 붙일 때 본인 이용인지 확인한다(403). 남의 이용 번호가 붙은 문의가 백오피스 문의함에 섞이는 것 자체가 정보 노출이다
- 사고 접수에는 상태 게이트를 두지 않았다 — 사고는 반납 뒤에 발견되기도 하고, 접수 시점을 막아서 얻을 게 없다. 본인 대여 확인만 한다(403)
- 면책 안내는 예약의 `insurance` **스냅샷**에서 파생한다. 상품이 나중에 개편돼도 가입 당시 조건으로 안내된다
- 사진은 선택(0~5장) — 사고 직후 촬영이 불가능한 상황이 있다. 반면 체크인/아웃은 사진이 증빙 자체라 필수(M1-2)

### 카테고리는 문서 초안(3종) 대신 DB enum(5종)을 따랐다

작업 문서 초안은 `VEHICLE`/`USAGE`/`ETC` 3종이었지만, M1-1 마이그레이션이 이미
`VEHICLE`/`RESERVATION`/`RETURN`/`ACCIDENT`/`ETC` 5종으로 확정돼 있었다. 초안의 `USAGE`가
예약·반납·사고로 나뉜 형태라 표현력이 줄지 않고, **추가 마이그레이션 없이** 더 세분화된
분류로 백오피스 문의함(M3-5)의 담당 배분이 쉬워진다.

### 웹

- `/inquiries` — 문의 작성 폼(유형·본문) + 내 문의함(상태 배지·운영 답변). AppShell 하단 탭에 "문의" 추가(로그인 시 노출)
- 사고 접수는 예약 상세 ③ 이용 중 단계 안에서: 버튼 → 설명+촬영 → 완료 화면(가입 면책상품·자기부담금·모의 보험사 안내 4단계)

### 테스트

- 백엔드 통합 4건(문의 접수→내 문의함/타인 격리 · 검증 400과 남의 이용 403 · 사고 응답의 면책 티어·자기부담금 · 사진 없는 접수/짧은 설명 400/타인 403) — `test/inquiry-incident.int-spec.ts`
- 프론트 9건: 문의 4건(목록·페이로드·검증 에러·서버 에러) + 사고 5건(완료 화면 면책 정보 · 자기부담금 있는 티어 · 사진 페이로드 · 검증 에러 · 서버 에러)
