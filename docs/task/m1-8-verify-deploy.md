## 결과 (2026-09-01)

### M1 전체 동선 E2E 통합 테스트 (`test/m1-e2e.int-spec.ts`, 12건)

프로덕션 스모크를 대신하는 자리다. 개별 기능의 경계 조건은 각 기능 스펙이 이미 덮으므로,
이 스펙이 보는 것은 **기능들이 이어 붙었을 때 한 예약이 끝까지 굴러가는가**다 —
M1이 병렬 트랙 두 개를 합친 결과라, 통합 지점이 실제로 맞물리는지 확인하는 자리.

한 예약(한 차량·한 사용자)의 전 생애를 순서대로 완주한다:

| # | 단계 | 확인하는 것 |
|---|---|---|
| ① | 예약 생성 | 선결제 1건 CAPTURED, 금액이 견적과 일치 |
| ② | 예약 변경 (시각 + 반납 존) | 편도 최소 수수료 5,000원, **차액만** 추가 승인(2번째 UPFRONT) |
| ③ | 이용 시작 | Rental IN_USE, `usage`가 "아무 단계도 안 끝남 + 차 잠김"을 보고 |
| ④ | **게이트** 체크인 전 스마트키 | 403 · 조작 로그 없음 · 차량 상태 불변 |
| ⑤ | 체크인 (사진 2장 + 메모) | 사진이 `data:` URI로 회신, `usage.checkIn` 반영 |
| ⑥ | 스마트키 | UNLOCK → IGNITION_ON → **시동 중 LOCK 400** → IGNITION_OFF → LOCK, 거절분은 로그에 없음 |
| ⑦ | 차종 매뉴얼 | 이 차의 연료(내연)에 맞는 주유/체크리스트 본문 |
| ⑧ | 연장 | 연장분(3,600원)만 3번째 UPFRONT로 결제 |
| ⑨ | **게이트** 체크아웃 전 반납 | 409 · Rental은 IN_USE 유지 |
| ⑩ | 체크아웃 (사진 + 주차 위치) | `usage.checkOut.parkingNote` 반영 |
| ⑪ | 반납·정산 | 주행거리 자동 확정, 정산이 요금 엔진과 일치(30km 무료 구간), 차량이 **반납 존으로 이동** |
| ⑫ | 사후 정합 | CAPTURED 합계 = 선결제 + 주행/지연요금 · 보고 2건/사진 3장 · 조작 로그 4건 |

게이트 위반 3종(④ 403 · ⑥ 400 · ⑨ 409)을 별도 스펙이 아니라 **같은 동선 안에서** 확인한다.

### 회귀 점검 — 병렬 트랙 통합 지점

- 예약 상세(`apps/web/src/app/reservations/[id]/page.tsx`)의 5단계 UI에 M1-5 변경 패널과
  M1-6 매뉴얼 링크가 연결돼 있고, `예약 상세 — 병렬 트랙 연결 지점` 테스트 2건이 이를 고정한다
- MSW 핸들러 26개 라우트에 중복 등록 없음, 픽스처는 파일 하나로 합쳐져 있고 금액이 서로 맞는다
  (편도 27,400 = 22,400+5,000 · 부름 28,400 = 22,400+6,000 · 완료 대여 252원 = (31.4−30)×180)
- M1-5·M1-6 작업 문서에 남아 있던 "⚠️ 남은 연결" 경고를 해소 기록으로 갱신했다

### 배포는 이번 세션 스코프 아웃

작업 문서 초안의 "main 머지 → 푸시 → 프로덕션 스모크"는 **사용자 결정으로 이번 세션에서 제외**했다.
`SEED_VERSION`은 M1-1에서 3으로 올라가 있어(신규 테이블 초기화 포함) 배포 시 자동 재시드 조건은
이미 충족돼 있고, 배포 시점에 추가로 손댈 것은 없다.
