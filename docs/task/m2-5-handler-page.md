## 결과 (2026-09-01)

### 화면

`/handler` 한 페이지에 탭 두 개 — **진행 중**(오늘 할 일 · 예정 · 수락 가능한 작업)과
**완료 이력**(오늘 / 이번 주). 큐는 `GET /handler/tasks` 한 번으로 다 채워진다.

- 카드는 "무슨 일 / 어디서 어디로 / 언제까지"만 담는다 — 타입 배지(🚚배달 ↩️회수 🔁재배치),
  지연이면 `⏰ 지연`, 기한과 A* 예상 이동 시간
- 공개 작업 카드에만 **수락** 버튼이 붙는다 (한 번 눌러 내 큐로)
- 상세는 바텀시트 모달. 지도(출발 🚩 → 도착 🏁)와 기한·차량·예상 이동을 보여주고,
  **지금 누를 수 있는 버튼 하나**만 크게 둔다: 수락 → 이동 시작 → 완료 처리
- 완료 입력(인계 사진 + 메모)은 이동 중 상태에서만 열리고, 제출 전에 서버와 같은
  shared 스키마(`completeHandlerTaskSchema`)로 먼저 검증한다 — 현장에서 사진을 다 찍고
  400을 받는 것보다 버튼을 누른 자리에서 알려주는 편이 낫다
- 완료하면 상세가 닫히고 이력 탭으로 넘어간다. 카드는 큐 재조회로 알아서 자리를 옮긴다

### 판단

- **`ZoneMap` 대신 `TaskRouteMap`(신규).** 홈의 지도는 존 탐색용(클러스터링·차량 수 배지·
  선택 시 flyTo)이라 두 지점을 잇는 용도와 맞지 않는다. 부름 위치 선택(`DeliveryMapPicker`)과
  같은 경량 지도 구성으로 출발·도착 마커와 직선 연결만 그린다 — 실제 소요 시간은 서버가
  A*로 계산해 응답에 실어 준다
- **내비 분기**: 핸들러에게는 `작업` 탭만 보이고 `예약`·`문의`는 감춘다. 핸들러는 이용자가
  아니라 현장 작업자다. 로그인 후 랜딩도 역할로 갈린다(`HANDLER` → `/handler`)
- 로그인 화면 데모 계정 목록과 README 데모 계정 표에 `handler@demo.mocar.kr` 추가
  (M2-1이 충돌 회피로 미뤄 둔 것)
- 이력의 오늘/이번 주는 화면이 `completedAt`으로 나눈다 (서버는 최근 7일 창을 준다)
