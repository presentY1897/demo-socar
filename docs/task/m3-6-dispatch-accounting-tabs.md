# M3-6 — 작업/배차 + 회계 탭 UI

- 마일스톤: M3 (운영 백오피스 재설계) · 규모 M
- 상태: ☑ 완료
- 의존: M3-3 (배차는 M2-4 API 사용)

## 목적

핸들러 배정을 화면으로 올리고(피드백 #5 "운송기사 배차"), 매출·손익을 회계 탭으로 격리한다(피드백 #4).

## 작업 내용

- [x] **작업/배차 탭**:
  - 미배정 작업 큐: 타입·차량·출발→도착·기한 — 배정 버튼 → 핸들러 선택 모달(거리순 추천, M2-4)
  - 진행 중 작업 보드(배정/이동 중), 핸들러별 오늘 처리량
  - REPOSITION 수동 생성 폼 (차량·출발/도착 존·기한)
- [x] **회계 탭**:
  - 월 손익 요약: 매출 − 비용(리스료+보험료+주차장 계약비) 카드
  - 기존 매출/예약/가동률 지표와 일별 차트를 이 탭으로 이동 (운영 홈에서 제거)
  - 차트는 일단 기존 라이브러리 그대로 옮기고, Chart.js 교체는 M4-1에서 일괄

### 설계 메모

- **작업 목록은 한 번만 받아 세 덩어리로 가른다**(`lib/ops-tasks.ts`의 `buildTaskBoard`). 상태별로 세 번 물으면 세 목록이 서로 다른 시점의 스냅샷이 되어 합계가 맞지 않는다.
  `GET /ops/tasks`의 서버 필터(`status`·`type`·`date`)를 쓰지 않고 전건을 받는 것은 **지금 규모에서의 선택**이다 — 조건이 바뀌는 지점(작업이 한 화면에 안 담길 때)과 근거는 [ADR-009](../adr/009-ops-backoffice-telemetry.md) 결정 1에 적었다
- **처리량은 "오늘 끝낸 것"만 센다** — 어제까지 합치면 처리량이 아니라 누적이 된다
- **후보는 서버가 준 순서 그대로** 보여준다. 순서 근거는 "마지막 완료 지점 → 출발지" 거리이고 점수 대신 근거 문장을 준다(M2-4). 화면이 다시 정렬하면 근거와 순서가 어긋난다
- **재배치 생성은 출발 존을 보내지 않는다** — 차량이 실제로 서 있는 곳을 서버가 채운다. 운영자가 고른 출발지와 실제가 다르면 아무도 수행할 수 없는 작업이 생긴다
- **회계는 매출(기간 집계)과 비용(월 고정비)의 성격이 다르다**는 점을 화면에 적었다. 적지 않으면 "90일로 넓혔더니 손익이 좋아졌다"는 착시가 생긴다

### M4-1이 교체할 차트 지점

| 파일 | 내용 |
|---|---|
| `apps/web/src/components/ops/AccountingCharts.tsx` | **유일한 Recharts 사용처.** 일별 예약 BarChart + 일별 매출 LineChart. 기존 `/dashboard`에서 그대로 옮겨 왔다 |

바깥(손익 카드·비용 구성 막대·운영 지표)에는 차트 라이브러리가 없다 — 비용 구성은
CSS 비율 막대라 M4-1 교체 대상이 아니다.
