# M3-3 — /ops API

- 마일스톤: M3 (운영 백오피스 재설계) · 규모 L
- 상태: ☑ 완료
- 의존: M3-2

## 목적

운영 센터 화면(M3-4~6)이 쓸 백엔드 전체. 기존 `/metrics`(매출 중심)는 회계 전용으로 강등한다.

## 작업 내용

- [x] **Fleet**: `GET /ops/fleet` — 전 차량: 상태(대기/운행/탁송/정비), 배정 존, 텔레메트리 요약(연료·주행거리), 다음 예약, 보험 만기 D-day / `GET /ops/fleet/:id` — 센서 상세 + 스마트키 조작 이력(VehicleControlLog) + 도입/보험(VehicleFinance) + 정비 메모
- [x] **차량 등록**: `POST /ops/vehicles` — 차량 + 도입 정보(VehicleFinance) + 텔레메트리 동시 등록, 존 배정
- [x] **존 계약**: `GET /ops/zones`(계약·면수·현재 배정 차량 수·잔여 자리) · `PATCH /ops/zones/:id/contract`
- [x] **유저 리스크**: `GET /ops/users/risk` — 유저별 지연 반납 횟수(30일)·사고 접수 수·결제 거절 수 집계, 임계치 초과만
- [x] **문의 답변**: `GET /ops/inquiries` · `POST /ops/inquiries/:id/answer` (M1-7 연계)
- [x] **회계**: `GET /ops/accounting/summary` — 매출(기존 metrics 재사용) + 비용(월 리스료+보험료+주차장 계약비 합산) → 월 손익. 기존 `/metrics/summary·daily`는 회계 탭 전용으로 유지
- [x] **경고 피드**: `GET /ops/alerts` — 연료 부족(<20%)·보험 만기 임박(D-30)·계약 만료 임박(D-30)·지연 반납 진행 중
- [x] 전 엔드포인트 OPS 역할 가드

### 작업 문서에 없던 추가 (화면이 요구해서 붙인 것)

| 엔드포인트 | 왜 |
|---|---|
| `GET /ops/overview` | M3-4의 운영 홈 상단 스탯(운행 중·탁송 중·오늘 예약·미배정 작업). 기존 엔드포인트 조합으로는 "오늘 예약 수"를 얻을 수 없다 |
| `POST /ops/fleet/:id/notes` | M3-4 상세 패널의 "정비 메모 입력". 목록은 `GET /ops/fleet/:id`가 이미 내려준다 |
| `GET /ops/users/:id` | M3-5의 "유저 클릭 → 최근 예약/사고 이력". 리스크 목록에 이력을 인라인으로 실으면 목록이 무거워지고 M4-4 CSV Export도 지저분해진다 |

### 설계 메모

- **경고 판정과 회계 합산은 순수 함수로 분리**했다(`alerts/alert-rules.ts` · `accounting/accounting-calc.ts`). 임계치(20% · D-30 · 리스크 문턱)는 `packages/shared/src/schemas/ops.ts`가 단일 소스라 화면과 어긋나지 않는다
- **연료 부족은 저장값이 아니라 조회 시점 계산값으로 판정**한다 — 운행 중인 차의 연료는 지금도 줄고 있어서 저장값만 보면 경고가 한 박자 늦는다
- **회계의 매출과 비용은 성격이 다르다**: 매출은 기간 집계(실제 결제) + 진행 중 리스 청구, 비용은 월 고정비(차량 리스료·보험료·주차장 계약비). `days`를 바꾸면 이용 매출만 움직인다 — 화면이 이 점을 표기해야 착시가 없다. 법인 리스료는 MOCAR 쪽에서 **매출**(LeaseContract), 차량 리스료는 **비용**(VehicleFinance)으로 방향이 반대다
- **유의 유저는 모델을 만들지 않고 집계**로 낸다 — 리스크는 저장할 상태가 아니라 지금 데이터를 보는 방식이라, 저장하면 원본과 어긋난 채 남는다. 3종 집계를 각각 질의 1회로 끝낸다
- **잔여 자리가 음수(초과 배정)여도 0으로 깎지 않는다** — 화면에서 숨기면 그 존으로 차를 계속 보내게 된다
- **문의 답변은 한 번만** 받는다(재답변 409). 덮어쓰면 이용자가 본 문구와 백오피스가 보는 문구가 갈린다
- **차량·다음 예약·텔레메트리를 각각 질의 1회**로 읽고 메모리에서 맞춘다 (차량 수만큼 질의가 늘지 않는다)
