# M3-2 — 텔레메트리 모의 엔진

- 마일스톤: M3 (운영 백오피스 재설계) · 규모 M
- 상태: ☐ 대기
- 의존: M3-1

## 목적

피드백 #5 "스마트 차량의 내부 센서 정보를 어떻게 뿌릴 건지". 실차 없이 그럴듯한 센서 값을 만드는 모의 엔진. **조회 시점 계산 + SSE 주기 갱신** 방식(Q4 기본값 — 백그라운드 워커 없음, 무료 티어 CPU 고려).

## 작업 내용

- [ ] 모의 규칙 (순수 함수로 분리, 단위 테스트 대상):
  - 대여 중(IN_USE): 마지막 갱신 이후 경과 시간 × 15~35km/h(기존 반납 모의와 동일 분포) → 위치는 존→반납 예정지 방향 보간, odometer 증가, 연료 100km당 ~12% 감소(EV는 완속 기준)
  - 탁송 중(EN_ROUTE 작업): A* 경로 위 보간
  - 대기 중: 변화 없음 (문 잠금/시동은 스마트키 조작 값 유지)
  - 반납/작업 완료 시: 그 시점 값으로 스냅샷 확정 저장
- [ ] 조회 경로: 텔레메트리를 읽는 모든 API가 "저장값 + 경과 시간 계산"으로 현재값 산출, 일정 간격(예: 60초) 넘으면 저장값 갱신(write-through)
- [ ] SSE: 기존 `/metrics/vehicles/live` 채널에 텔레메트리 필드 포함, 5초 틱

## 산출물

- `apps/api/src/telemetry/`(모의 엔진 + 서비스) · SSE 페이로드 확장

## 완료 기준

- 단위 테스트: 경과 시간 시나리오별 연료/주행거리/위치 값 · 대기 중 불변 · 반납 스냅샷
- 운행 중 차량이 SSE에서 5초마다 움직임

## 테스트

- **백엔드(단위, 순수 함수)**: 경과 시간별 연료/주행거리/위치 값 · 대기 중 불변 · 반납 시 스냅샷 확정 · EV/내연 감소율 차이 / SSE 페이로드에 텔레메트리 포함 통합 1건
- **프론트**: 해당 없음
